## 1. Введение
Поиск кратчайших путей представляет собой фундаментальную задачу теории графов, имеющую ключевое значение для таких областей, как сетевая маршрутизация, логистическое планирование и анализ социальных сетей. Классический алгоритм Дейкстры обеспечивает её эффективное решение для графов с неотрицательными весами рёбер. Поскольку многие реальные графы являются разреженными, для оптимизации вычислений и работы с памятью в данной работе используется формат CRS (Compressed Row Storage). Этот подход минимизирует затраты памяти за счёт хранения только ненулевых элементов и позволяет эффективно получать данные о смежных вершинах.

С постоянным ростом масштабов и сложности обрабатываемых графов возрастает актуальность разработки высокопроизводительных вычислительных методов. Параллельная реализация алгоритма Дейкстры позволяет задействовать ресурсы современных многоядерных систем, что открывает возможности для значительного ускорения обработки больших объёмов данных. Целью данной работы является исследование возможностей такого параллельного подхода. Работа включает реализацию параллельной версии алгоритма, адаптированной под формат CRS, и её сравнительный анализ с классической последовательной реализацией для оценки достижимого ускорения и эффективности распараллеливания.

## 2. Постановка задачи
Пусть дан взвешенный ориентированный граф $G = (V, E)$, где $V$ — множество вершин, $E$ — множество рёбер. Каждому ребру $(u, v) \in E$ сопоставлен неотрицательный вес $w(u, v) \in \mathbb{R}_{\geq 0}$. Задана стартовая вершина $s \in V$.

Необходимо для каждой вершины $v \in V$ найти длину кратчайшего пути от $s$ до $v$, то есть минимально возможную сумму весов рёбер вдоль любого пути из $s$ в $v$. Если путь из $s$ в $v$ не существует, длина считается бесконечной.

**Входные данные:** 
* Граф представлен в формате CRS:
  * `weights` (`std::vector<double>`) — одномерный массив, в котором последовательно записаны веса всех рёбер графа (ненулевые элементы матрицы смежности).
  * `edges` (`std::vector<int>`) — одномерный массив той же длины, что и `weights`. Элемент `edges[j]` хранит номер вершины-назначения (номер столбца) для ребра, вес которого хранится в `weights[j]`.
  * `offsets` (`std::vector<int>`) — одномерный массив длиной `(vertices + 1)`. Элемент `offsets[i]` содержит начальный индекс в массивах `weights` и  `edges`, соответствующий рёбрам, исходящим из вершины `i`. Рёбра вершины `i` расположены в интервале индексов `[offsets[i], offsets[i+1])`. Последний элемент `offsets[vertices]` равен общему количеству ненулевых элементов (рёбер).
* `vertices` — общее число вершин в графе.
* `source` — стартовая вершина.

**Выходные данные:** вектор расстояний `dist` (`std::vector<double>`), содержащий длину кратчайших расстояний от `source` до каждой из вершин.

**Ограничения:** веса всех ребер графа неотрицательны ($\forall (u,v) \in E, w(v, u) \geq 0$).

## 3. Последовательный алгоритм
Последовательный алгоритм реализует классический алгоритм Дейкстры для поиска кратчайших путей от заданной стартовой вершины ко всем остальным вершинам взвешенного графа.

 **Алгоритм:**
 1. ***Инициализация:*** 
    - Создание массив расстояний, в котором всем вершинам присваивается бесконечно большое значение, кроме стартовой вершины, которая получает расстояние 0.
    - Инициализация массив отметок о посещении вершин (изначально для всех вершин `false`).
    - Создание приоритетной очереди (`min-heap`), помещение туда стартовой вершины с расстоянием 0.
 2. ***Основной цикл обработки:***
    Пока очередь с приоритетом не пуста:
    - Извлекается вершина с наименьшим расстоянием из очереди.
    - Если вершина уже ещё не была обработана, то она помечается как посещённая (в ином случае пропускается).
    - Для всех соседних вершин текущей вершины:
      - Вычисляется потенциальное новое расстояние как сумма расстояния до текущей вершины и веса ребра к соседу.
      - Если вычисленное расстояние меньше текущего известного расстояния до соседа, то соседняя вершина с новым расстоянием добавляется в очередь приоритетов. 
 3. ***Постобработка результата:***
    - Все оставшиеся бесконечные расстояния (обозначающие недостижимые вершины) заменяются на специальное значение -1.

## 4. Параллельный алгоритм
В качестве параллельного алгоритма был использован алгоритм для направленного графа авторов Краузер, Мельхорн, Мейерс, Сандерс, 1998г. 
### 4.1 Структура данных и распределение
Граф из `n` вершин равномерно распределяется между `p` процессами: каждому процессу назначается непрерывный диапазон вершин: `[st_vert_, en_vert_)`. 

Размер локального диапазона вычисляется по формуле: `local_n_ = delta_ + (rank < extra_ ? 1 : 0)`, где `delta_ = n / p`, `extra_ = n % p` - равномерное распределение с остатком.

**Локальные структуры данных каждого процесса:**
- `local_d_` - массив расстояний для локальных вершин
- `min_in_`, `min_out_` - минимальные веса входящих и исходящих рёбер для каждой локальной вершины
- Три очереди с приоритетом:
  - `qd_` - очередь по расстоянию `d[v]`
  - `qin_` - очередь по `in[v] = d[v] - min_in_[v]`
  - `qout_` - очередь по `out[v] = d[v] + min_out_[v]`

### 4.2 Основные этапы алгоритма
#### 1. Подготовительный этап (PreProcessingImpl)

1. Загрузка мастер-процессом (rank 0) входных данных
2. Вычисление глобальных минимальных весов рёбер (`CalculateGlobalMinInOut`)
3. Широковещательная рассылка параметров распределения (`BroadcastParameters`)
4. Инициализация локальных диапазонов вершин для каждого процесса
5. Рассылка данных о графе всем процессам (`BroadcastGraphData`)

#### 2. Основной цикл вычислений

Алгоритм работает итеративно до выполнения глобального критерия остановки:

**2.1. Асинхронный приём сообщений:** `RecieveData(flag, status);`
- Каждый процесс постоянно проверяет наличие входящих сообщений.
- При получении сообщения с новым расстоянием до вершины:
    - Если вершина принадлежит локальному диапазону процесса и новое расстояние меньше текущего, то обновляется `local_d_` и соответствующие очереди.

**2.2. Определение множества вершин, готовых к обработке:**
- Вычисление глобальных минимумов `L` (минимальный приоритет по всем `qout_`) и `M` (минимальный приоритет по всем `qd_`) при помощи `MPI_Allreduce`
- Формирование локального множества `R` вершин, удовлетворяющих критерий: `d[v] ≤ L` или `in[v] ≤ M`, а следовательно готовых к обработке.

**2.3. Обработка локального множества R:**

Для каждой вершины `u` в `local_r` производится обход всех исходящих из неё рёбер:
  - Для каждой смежной вершины `v` определяется её владелец (процесс, которому она принадлежит)
      - Если владелец - текущий процесс: локальное обновление
      - Иначе: асинхронная отправка сообщения владельцу (`MPI_Isend`)

**2.4. Синхронизация и очистка:**
- Ожидание завершения всех исходящих запросов (`MPI_Waitall`)
- Удаление обработанных вершин из очередей
- Проверка глобального критерия остановки

#### 3. Критерий остановки (`IsGlobalStop`)

Алгоритм завершается, когда одновременно выполняются условия:
- Все локальные очереди пусты
- Нет ожидающих сообщений во всей системе

Результаты лабораторной работы подтверждают принципиальную возможность ускорения алгоритма Дейкстры за счёт распараллеливания, однако также выявляют существенную зависимость эффективности от структуры графа и коммуникационных характеристик вычислительной системы.

bool RomanovaVDijkstraCrsMPI::PreProcessingImpl() {
  delta_ = 0;
  extra_ = 0;

  int rank = 0;
  int n = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &n);

  if (rank == 0) {
    SetupMasterProcessData();
  }

  BroadcastParameters();
  SetupLocalVertexRange(rank);
  InitializeLocalArrays();
  SetupMinInOutArrays(rank, n);
  InitializeQueues();
  BroadcastGraphData(rank);

  return true;
}

void RomanovaVDijkstraCrsMPI::InitializeSource() {
  if (st_vert_ <= data_.source && data_.source < en_vert_) {
    local_d_[data_.source - st_vert_] = 0.0;
    UpdateQueues(data_.source - st_vert_);
  }
}

bool RomanovaVDijkstraCrsMPI::RunImpl() {
  int rank = 0;
  int n = 0;

  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &n);

  InitializeSource();

  bool global_stop = false;

  while (!global_stop) {
    MPI_Status status;
    int flag = 0;

    RecieveData(flag, status);

    double global_l = GetGlobalMin(qout_);
    double global_m = GetGlobalMin(qd_);

    std::vector<int> local_r;
    MakeLocalR(local_r, global_l, global_m);

    for (int v : local_r) {
      RemoveFromQueues(v);
    }

    ProcessLocalR(local_r, flag, status);

    MPI_Barrier(MPI_COMM_WORLD);

    CleanUpQueues();

    global_stop = IsGlobalStop();
  }

  MPI_Status final_status;
  int final_flag = 0;
  MPI_Iprobe(MPI_ANY_SOURCE, 2, MPI_COMM_WORLD, &final_flag, MPI_STATUS_IGNORE);
  if (final_flag != 0) {
    RecieveData(final_flag, final_status);
  }

  MPI_Barrier(MPI_COMM_WORLD);

  std::vector<int> vert_sendcounts(n, delta_);
  std::vector<int> vert_displs(n, 0);

  if (rank == 0) {
    vert_sendcounts = CalculateVertexSendCounts(rank, n);
    vert_displs = CalculateVertexDisplacements(rank, n, vert_sendcounts);
  }

  res_weights_.assign(data_.vertices, 0.0);

  MPI_Gatherv(local_d_.data(), local_n_, MPI_DOUBLE, res_weights_.data(), vert_sendcounts.data(), vert_displs.data(),
              MPI_DOUBLE, 0, MPI_COMM_WORLD);
  if (rank == 0) {
    for (int i = 0; i < data_.vertices; i++) {
      if (res_weights_[i] == std::numeric_limits<double>::infinity()) {
        res_weights_[i] = -1;
      }
    }
  }
  MPI_Bcast(res_weights_.data(), data_.vertices, MPI_DOUBLE, 0, MPI_COMM_WORLD);

  return true;
}
